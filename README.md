# Блокировка рекламы через свой сервер Amnezia

Гайд и скрипт для настройки блокировки рекламы для всех устройств,
подключённых к вашему собственному серверу Amnezia (AmneziaWG / OpenVPN на VPS),
плюс отдельно — как убрать рекламу **в самом YouTube**.

---

## ⚠️ Сначала — важная правда про YouTube

**Через VPN-сервер и DNS-блокировку убрать видео-рекламу внутри YouTube нельзя.**

YouTube отдаёт и сами ролики, и видео-рекламу (pre-roll, mid-roll) с одних и тех
же серверов — `*.googlevideo.com`. Если заблокировать их на DNS — вместе с
рекламой перестанет грузиться и само видео. Поэтому классическая схема
«поставил AdGuard/Pi-hole на сервер → нет рекламы в ютубе» **не работает**
именно для видео-рекламы YouTube.

Правильный подход — **комбинация двух уровней**:

| Уровень | Что решает | Инструмент |
|---|---|---|
| **Сервер (DNS)** | Реклама и трекеры во **всех** приложениях и на сайтах, сразу для всех VPN-устройств | AdGuard Home на сервере Amnezia |
| **Клиент** | Реклама **в самом YouTube** (ролики, баннеры) | uBlock Origin / ReVanced / SmartTube |

---

## Часть 1. Серверный уровень — AdGuard Home на сервере Amnezia

Даёт блокировку рекламы, трекеров и вредоносных доменов **для всех устройств**,
подключённых к VPN, без настройки каждого устройства отдельно.

> Уберёт: баннеры на сайтах, трекеры, рекламу во многих приложениях, часть
> Google-рекламы (`doubleclick.net`, `googleadservices.com`).
> **Не уберёт:** видео-рекламу внутри YouTube (см. Часть 2).

### Установка

Подключитесь к серверу по SSH (тот же VPS, где стоит Amnezia) и запустите:

```bash
git clone https://github.com/kostya4118/archer_ax55_vpn.git
cd archer_ax55_vpn
sudo bash install-adguard.sh
```

Скрипт:
1. Освободит порт `53` (отключит `DNSStubListener` у `systemd-resolved`).
2. Установит AdGuard Home официальным установщиком.
3. Предложит закрыть DNS от интернета, оставив доступ только из VPN-подсети
   (рекомендуется — чтобы сервер не стал «открытым резолвером»).

Если ваша VPN-подсеть отличается от `10.8.1.0/24`, укажите свою:

```bash
sudo VPN_SUBNET="10.8.0.0/24" bash install-adguard.sh
```

### Первичная настройка

1. Откройте в браузере `http://IP_СЕРВЕРА:3000`.
2. Задайте логин и пароль.
3. Веб-интерфейс — порт `80` или `8080`; **DNS-сервер (Listen) — порт `53`**.
4. Добавьте блок-листы (см. ниже).

### Блок-листы

В AdGuard Home → **Фильтры → Чёрные списки DNS → Добавить**:

```
# AdGuard DNS filter (реклама + трекеры)
https://adguardteam.github.io/HostlistsRegistry/assets/filter_2.txt

# OISD Big — большой сбалансированный список
https://big.oisd.nl

# Трекеры (Peter Lowe)
https://pgl.yoyo.org/adservers/serverlist.php?hostformat=adblockplus&showintro=1&mimetype=plaintext

# Реклама в мобильных приложениях
https://adguardteam.github.io/HostlistsRegistry/assets/filter_11.txt

# (RU) Реклама на русскоязычных сайтах
https://adguardteam.github.io/HostlistsRegistry/assets/filter_14.txt
```

> Не добавляйте «античит»/YouTube-специфичные хаки в DNS — они ломают
> воспроизведение видео и не убирают рекламу. Для YouTube — только Часть 2.

### Подключение DNS к Amnezia

Чтобы VPN-клиенты пользовались вашим AdGuard, они должны ходить в DNS
**на сервер по внутреннему адресу VPN** (а не на внешний IP — так безопаснее).

- **Внутренний адрес сервера** — это адрес wg/awg-интерфейса, обычно `.1` в
  вашей подсети (например `10.8.1.1`). Посмотреть можно на сервере:
  ```bash
  ip -4 addr show | grep -A2 -E 'wg|awg|tun'
  ```
- **В приложении Amnezia:** откройте настройки сервера → раздел с DNS
  (в разных версиях называется «DNS-серверы» / «Custom DNS») → пропишите
  этот внутренний адрес как **основной DNS**. Вторичный можно оставить пустым
  или указать тот же адрес.
- Если правите конфиг вручную (`wg0.conf` / клиентский `.conf`), в секции
  `[Interface]` укажите:
  ```
  DNS = 10.8.1.1
  ```
- Переподключите VPN и проверьте, что реклама на сайтах пропала.

### Проверка

На подключённом к VPN устройстве откройте:
- https://adblock-tester.com — покажет процент заблокированного;
- в панели AdGuard Home → **Журнал запросов** должны идти запросы от клиентов.

## Часть 1b. Особый случай: Amnezia в Docker (`amnezia-dns-net`)

Если Amnezia развёрнута **в Docker-контейнерах** (`docker ps` показывает
`amnezia-awg`, `amnezia-awg2` и т.п.), то wg-интерфейс спрятан **внутри**
контейнера, а на хосте вместо `wg0` вы видите bridge-интерфейс (например
`amn0`) с адресом вида `172.29.172.1`. Контейнеры подключены к docker-сети
`amnezia-dns-net`.

В этом случае:
- **DNS-адрес для клиентов** — это адрес хоста в docker-сети (шлюз), обычно
  `172.29.172.1`. Клиенты достучатся до него через контейнер.
- **Firewall** нужно открывать не для wg-подсети `10.8.1.0/24`, а для
  **docker-подсети** (`172.29.172.0/24`) — потому что запросы приходят на хост
  уже под адресом контейнера (`172.29.172.2/.3`).

### Автоматическая настройка

Вместо ручной правки DNS на каждом устройстве проще включить **прозрачный
перехват DNS** на сервере — тогда все клиенты пойдут в AdGuard автоматически:

```bash
sudo bash setup-amnezia-dns-redirect.sh
```

Скрипт сам определит docker-сеть, подсеть и bridge, разрешит порт 53 и поставит
перехват (DNAT: любой запрос на порт 53 → AdGuard на хосте), затем сохранит
правила. Параметры можно задать вручную:

```bash
sudo ADGUARD_IP=172.29.172.1 NET_SUBNET=172.29.172.0/24 BRIDGE_IF=amn0 \
  bash setup-amnezia-dns-redirect.sh
```

### Что делает скрипт (если хотите вручную)

```bash
# 1. Разрешить порт 53 из docker-подсети Amnezia
iptables -I INPUT -p udp --dport 53 -s 172.29.172.0/24 -j ACCEPT
iptables -I INPUT -p tcp --dport 53 -s 172.29.172.0/24 -j ACCEPT

# 2. Прозрачный перехват: весь DNS с порта 53 -> AdGuard на хосте
iptables -t nat -A PREROUTING -i amn0 -p udp --dport 53 ! -d 172.29.172.1 -j DNAT --to-destination 172.29.172.1
iptables -t nat -A PREROUTING -i amn0 -p tcp --dport 53 ! -d 172.29.172.1 -j DNAT --to-destination 172.29.172.1

# 3. Сохранить правила
apt-get install -y iptables-persistent && netfilter-persistent save
```

### Проверка (перехват работает даже для «чужого» DNS)

```bash
docker exec amnezia-awg nslookup google.com 172.29.172.1     # обычный домен -> реальный IP
docker exec amnezia-awg nslookup doubleclick.net 1.1.1.1     # реклама -> 0.0.0.0 (перехвачено!)
```

Если рекламный домен вернул `0.0.0.0` даже при запросе к `1.1.1.1` — значит
перехват работает, и все клиенты фильтруются без правки конфигов.

> При таком подходе прописывать DNS на устройствах вручную (Часть 1, «Подключение
> DNS к Amnezia») не нужно — перехват делает это за вас.

## Часть 1c. Видеореклама YouTube на уровне сети: выход через страну без рекламы

Единственный сетевой способ, который реально бьёт по **роликам-рекламе** YouTube
(а не только по баннерам), основан на официальной механике YouTube:

- У YouTube есть «монетизируемые рынки» (~100+ стран) — только там работает
  рекламный аукцион и показывается видеореклама.
  Официальный список: https://support.google.com/youtube/answer/1342206
- В остальных странах (Узбекистан, Армения, Монголия, Албания, Камбоджа и др.)
  рекламный рынок не запущен — видеорекламы нет или почти нет.
- Особый случай: в России Google приостановил показ своей рекламы с марта
  2022 — с российского IP видеорекламы YouTube нет вообще.

**Идея:** только YouTube-трафик (`youtube.com`, `googlevideo.com`, `ytimg.com`…)
выпускается через туннель в немонетизируемую страну; весь остальной трафик идёт
как раньше. Работает для всех VPN-клиентов сразу.

### Что нужно
Дешёвый VPS в немонетизируемой стране (Ташкент / Ереван / Улан-Батор и т.п.).
Перед покупкой проверьте, что страны **нет** в списке монетизируемых рынков.

### Настройка

1. **На втором VPS** (страна без рекламы):
   ```bash
   sudo bash noads-exit/remote-exit-setup.sh
   ```
   Скрипт поднимет WireGuard-сервер и напечатает готовый клиентский конфиг.

2. **На основном сервере** сохраните напечатанный блок в
   `/etc/wireguard/wgnoads.conf` и запустите:
   ```bash
   sudo bash noads-exit/local-route-setup.sh
   ```
   Скрипт: включит сбор IP YouTube-доменов в ipset через AdGuard Home
   (`dns.ipset`), поставит маркировку пакетов (fwmark) + policy routing в
   туннель, NAT и автозапуск после перезагрузки.

3. **Проверка:**
   ```bash
   wg show wgnoads                          # есть handshake
   curl -s --interface wgnoads ipinfo.io    # страна выхода = нужная
   ipset list youtube | head                # IP появляются после захода на ютуб
   ```
   Затем откройте популярный ролик на клиенте **без входа в Google-аккаунт**.

### Честные оговорки
- Для залогиненных аккаунтов таргетинг обычно тоже идёт по IP, но страна
  аккаунта может частично влиять — проверяйте на своём.
- Это опора на политику Google: если страна станет монетизируемой, эффект
  исчезнет (лечится сменой exit-страны).
- Скорость роликов ограничена каналом второго VPS.

## Часть 2. Клиентский уровень — реклама в самом YouTube

Здесь — то, что действительно убирает рекламу **внутри YouTube**. Выберите под
свою платформу:

### 💻 Компьютер (браузер)
- **[uBlock Origin](https://ublockorigin.com/)** — расширение для Chrome/Firefox/Edge.
  Полностью убирает рекламу в YouTube и на сайтах. Бесплатно.
- **[SponsorBlock](https://sponsor.ajay.app/)** — дополнительно пропускает
  спонсорские вставки внутри роликов.
- Браузер **[Brave](https://brave.com/)** — встроенная блокировка, если не
  хотите ставить расширения.

### 📱 Android
- **[ReVanced](https://revanced.app/)** — пересобранный клиент YouTube без
  рекламы (преемник Vanced). Ставится через ReVanced Manager.
- Либо браузер **Brave** / **Firefox + uBlock Origin** для просмотра YouTube
  через браузер.

### 📺 Android TV / приставка / телевизор
- **[SmartTube](https://github.com/yuliskov/SmartTube)** — клиент YouTube для
  ТВ без рекламы. Ставится как APK.

### 🍎 iPhone / iPad
- Браузер **Brave** (встроенная блокировка) — самый простой путь.
- **[uYou+](https://github.com/qnblackcat/uYouPlus)** — модифицированный клиент
  (требует сайдлоад через AltStore/Sideloadly).

### 🖥 macOS
- Браузер Safari + расширение **[AdGuard for Safari](https://adguard.com/adguard-safari/overview.html)**,
  либо Chrome/Firefox + uBlock Origin.

## Итоговая рекомендация

1. **Поставьте AdGuard Home на сервер Amnezia** (`install-adguard.sh`) —
   реклама и трекеры исчезнут во всех приложениях и на сайтах сразу для всех
   ваших устройств.
2. **Для YouTube добавьте клиентское решение** из Части 2 под каждую платформу.

Вместе это даёт «чистый» интернет без рекламы, включая сам YouTube.

## FAQ

**Почему нельзя убрать рекламу YouTube одним лишь сервером?**
Реклама и видео идут с одних доменов `*.googlevideo.com`; блокировка домена
ломает и видео. Отличать рекламные потоки от обычных на лету DNS не умеет.

**AdGuard Home замедлит интернет?**
Нет, наоборот — заблокированные запросы к рекламе/трекерам не выполняются,
страницы часто грузятся быстрее.

**Безопасно ли открывать DNS наружу?**
Нет — открытый резолвер используют для DDoS-атак с усилением. Скрипт по
умолчанию закрывает порт `53` от интернета и оставляет доступ только из VPN.

**Что если VPN-подсеть другая?**
Посмотрите адрес wg/awg-интерфейса на сервере (`ip -4 addr`) и передайте
`VPN_SUBNET` при запуске скрипта.
